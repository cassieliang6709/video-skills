# 科普写法（2026-10-24 沉淀，sys-04 进程篇第一版"大家听不懂"之后）

适用于所有逐字稿。默认受众：**会 Python、相关课程基本忘光了的大学生**。
第一版失败的原因：零基础检查用的是"上过课的学生"，它每轮都挑精确性（寄存器个数、xv6 调度路径），
稿子越改越准，也越来越难懂。准确由事实核对负责，好懂由零基础检查负责，两件事分开做。

## 七条写法

1. **先具体，后抽象**（3Blue1Brown："concrete before abstract"）。
   每章第一句是观众做过、见过的事：按 Ctrl-C、`kill -9`、活动监视器、`ls > out.txt`、`print` 输出两遍、Python 按 Ctrl-C 没反应。
   不要用定义开头。反例是 Wikipedia 讲信号："异步通知、进程间通信"。

2. **"如果让你来设计"**（闪客《你管这破玩意叫操作系统》的套路）。
   先让观众面对问题，再给一个朴素方案，让它当场失败，然后才讲真实机制。最后一步才给名字："这个叫中断。"
   例：让程序自觉交还 CPU → 死循环永远不交 → 只能靠程序管不了的硬件定时器。

3. **一张物理图贯穿全片**。开头画好"数据在哪、在哪执行、怎么跳过去再跳回来"，后面所有内容都回到这张图上讲，不另起新图。
   例：CPU、一张"执行到哪了"的记录卡、上层用户程序、下层内核；异常、系统调用、切换、信号都是"记卡 → 跳下去 → 跳回来"。

4. **术语预算**：每集新术语 ≤ 6 个；每句只推进一个点。
   名字出现之前，观众必须已经看到它指代的东西。只需要记住名字的，明说"记住这个名字就行"。
   一个术语在主线里出现后至少要用三次，只出现一次的就别起名字，直接描述它。

5. **类比只讲一个点**（Julia Evans：strained analogies）。一句话讲完，马上回到正题，不展开成一个世界观。
   一个概念最多一个类比。例：中断是门铃，轮询是每隔一会儿去开门看；pending 位像"有未读"的红点，来几条消息都只亮一个点。

6. **真实运行当证据**（Julia Evans：unsupported statements）。每个"凭什么"都尽量用一次真实运行来回答：缺页计数、SIGILL、16 个死循环抢 8 个核。
   这些也是高潮点。用"先猜一下"引出，再给结果。

7. **主线讲懂，进阶讲细**。寄存器、源码、具体指令这类细节放进每集末尾的"进阶"章（`chK | 进阶：…`）。
   开头一句标明"只想懂原理的可以停在这"。进阶章可以用术语，但同样要回到那张物理图上讲。
   主线里不提进阶才会出现的名词。

## 写完自查（Julia Evans《confusing explanations》里和我们相关的几条）

| 难懂的写法 | 改成 |
|---|---|
| 对读者知识的预设前后不一（前面解释 for 循环，后面直接用 malloc） | 写给一个具体的人："会 Python、OS 课忘光了的同学" |
| 一段塞好几个概念 | 一个概念一段，配一个能看到的例子或输出 |
| 从抽象讲起 | 从观众做过的事讲起 |
| 术语有了，但读者拿不到信息 | 删掉术语，直接说它解决了什么具体问题 |
| 结论没有证据 | 给一次能复现的真实运行 |
| 例子不真实（拿 lambda 求平方当例子） | 用真会遇到的场景（训练任务收到 SIGTERM 存 checkpoint） |
| 先演示错的做法，却不说它是错的 | 先说"这是个会失败的做法"，再演示 |
| 只讲是什么，不讲为什么 | 每个机制先讲"没有它会怎样" |

## 检查 agent 怎么设定

- **零基础检查（3b）**："你会写 Python，操作系统 / 本主题的课基本忘光了。"
  只标三类：听不懂的句子（哪个词、哪里跳步）；跟不上的地方（一句里新东西太多、要倒回去重看）；画面和旁白对不上。
  要它指出具体缺哪一步解释，尤其检查“问题 → 设计动机 → 机制 → 结果”是否连得上。可以建议补必要步骤、例子或精确性；不要为补细节引入与主线无关的新概念。
- **事实核对（3c）**：另起一个 agent，给它 script.md 和笔记。只标说错的地方；简化可以，比如"这里合成一次讲"。
  **不许它要求补充知识点或边界条件**。它提出的修正，优先用"换一个准确但同样简单的说法"来落实，不要往句子里堆限定语。
- 两个 agent 的意见冲突时，寻找既准确又好懂的表达；不能保留事实错误。教学性简化可能被误认为严格定义时，在旁白里用一句"这里简化了"交代。

## 参考 UP 主（2026-10-24 用户推荐）

依据的材料：B 站视频页的标题、简介、时长，用户截的主页图，一篇行业拆解文章（woshipm《Vibe 知识》）。没拿到字幕（要登录），所以下面只写能从这些材料确认的东西。

### 比特新语（2–3 分钟，单条 27 万–440 万播放）
- **标题是一句反常识的话，常带一个数字**：「我爱你」说到第 1000 遍，信息量几乎为零；你闻到的海的味道，其实不是盐；每一个也许都要付钱：0.8⁵ = 33%。
  → 我们每集的标题和封面钩子也写成一句反常识的话：「一行 printf，输出了两遍」「按一下 Ctrl-C，死循环为什么会停」。
- **一个比喻撑起整条视频的结构**：《脑内擂台》把大脑区域比作擂台选手，分三个回合讲上瘾、拖延、自控，简介里注明"拟人系认知隐喻，仅供参考"。
  → 允许用一个结构比喻来组织小节（比如"三种打断"三个回合），但只组织结构，不展开成世界观，第一次出现时明说"这是个比喻"。
- **先讲人人有过的体验，最后回到生活**：熵增落到"房间不打扫就会乱"。
  → 开头用观众做过的事，结尾回到观众自己的代码（Python 按 Ctrl-C、训练任务收到 SIGTERM）。
- 画面：暗色背景、发光线条、粒子，跟着 BGM 卡点，节奏像 MV（拆解文章的描述）。我们的画风已经定了，只借鉴"动画跟着旁白的节拍切换"这一点。

### Redknot-乔红（11–17 分钟，单条 15 万–224 万播放）
- **一条视频只讲一个看得见、摸得着的东西**：SSD、机械硬盘、HBM、手柄震动、键盘轴体、光刻机。标题统一是「用最好的动画为你讲解——X 的原理」。
  → 系统篇也要有一个"物"。软件概念没有实物，就用那张贯穿全片的物理图当"物"（CPU、执行到哪了的记录、用户程序、内核），每集都回到它身上。
- **长视频照样有人看**：单主题能做到 12–17 分钟（讲色域的那条有 39 分钟）。前提是每一分钟都在展示这个东西怎么动。
  → 内容丰富、讲懂优先，一篇合计 ~30 分钟没问题；凑时长的段落一律删掉，但需要的分步演示不要为了省时间砍掉。
- **封面就是那个东西的大图 + 3–6 个字的白色粗体**（固态硬盘的原理、HBM 的原理、先进封装）。
  → 和 cover-guide.md 的"右侧一个大视觉物"一致：右边放这一集的物理图或真实输出，左边放钩子。
- 简介只有一句："本期视频使用 3D 动画讲解了……的运行原理"。

### 两位共同的地方
1. 一条视频只回答一个问题，标题就是这个问题，或者是它的反常识答案。
2. 用画面里的东西来讲，不靠术语：观众一直在看某个具体的东西在动。
3. 结论是一句能转述给别人的话（"信息量几乎为零""死循环卡不死机器，是因为定时器中断不归它管"）。
